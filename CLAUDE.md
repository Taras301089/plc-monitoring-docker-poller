## 📋 Управление задачами

**Когда даете список задач:**
- Структурируйте задачи нумерованным списком в одном сообщении
- Я буду выполнять по одной и отслеживать статус
- После выполнения каждой задачи отчитываюсь и жду вашей проверки; commit делаю только после подтверждения (см. раздел «Пошаговое выполнение»)
- В конце покажу чеклист всех выполненных работ

**Пример:**
```
Задачи:
1. [ ] Убрать id из селектора, показать IP и статус
2. [ ] Перевести интерфейс на русский
3. [ ] Переименовать табы навигации
4. [ ] Добавить индикатор подключения
```

**Приоритеты:**
- Первый запрос: обновляю/добавляю этот раздел в MD
- Каждая проверенная и подтверждённая задача: один commit (после вашего согласия)
- Тестирование: после каждого изменения загружаю в браузер и проверяю

## 🐢 Пошаговое выполнение (договорённость)

- Делать **один запрошенный шаг за раз**: изменить, пересобрать, проверить, коротко отчитаться и **ждать подтверждения** перед следующим шагом
- Не забегать вперёд: не добавлять то, о чём не просили (новые функции, данные в БД, новые таблицы, правки справки), а **предлагать** это отдельно
- Крупные задачи (дашборды, отчёты, схемы БД, фоновые сборщики данных): сначала короткий план и согласование каждого шага, потом код
- Запись данных в БД пользователя и создание таблиц — только с явного согласия
- **Коммит и push** — только после того, как пользователь проверил результат; предложить можно, делать только по согласию

## Автоматическое тестирование фронтенда после изменений

После любых изменений файлов в `fastapi-api/static/`:

### Процесс:
1. **Пересобрать контейнер** (без кэша):
   ```bash
   docker compose down fastapi-api && docker compose build --no-cache fastapi-api && docker compose up -d fastapi-api
   ```

2. **Открыть браузер и протестировать**:
   - Использовать встроенный браузер: `mcp__Claude_Browser__preview_start`
   - URL: `http://localhost:8000`
   - Ctrl+Shift+R для очистки кэша

3. **Проверить функциональность**:
   - ✅ Страница загружается без ошибок
   - ✅ Кнопки "Обновить с ПЛК" и "Загрузить из БД" работают
   - ✅ Кнопки "Развернуть все" / "Свернуть все" работают
   - ✅ Data Blocks развертываются/сворачиваются при клике
   - ✅ Переменные отображаются внутри Data Blocks
   - ✅ Чекбоксы (выбор, архив, Grafana, авария) работают
   - ✅ "Сохранить выбранные" работает

4. **Если тесты не пройдены**:
   - Добавить `console.log()` для отладки в браузере
   - Проверить `read_network_requests` чтобы увидеть что приходит с API
   - Исправить код и повторить с шага 1

## Веб-интерфейс PLC Variable Browser

**Путь**: `fastapi-api/static/index.html`  
**API сервер**: `fastapi-api/main.py`  
**Три области вкладки «Переменные ПЛК»** (называть именно так):
1. **ПЛК** — выбор и настройка ПЛК (добавить/изменить/удалить), дата последнего обновления с ПЛК
2. **Блоки данных** — список Data Blocks, кнопки «Обновить с ПЛК» / «Из БД», поиск и сортировка
3. **Переменные** — переменные выбранного блока (плоский нумерованный список, структуры раскрываются)

**Функции**:
- Иерархическое отображение переменных (древовидная структура как в WinCC)
- Развернуть/свернуть Data Blocks
- Поиск по Data Block и имени переменной
- Выбор переменных для сохранения
- Опции: архивирование, Grafana, авария

## 🎨 Стиль оформления: Flat Dark (плоский тёмный с акцентами)

- Цвета только через CSS-переменные из `:root` / `[data-theme="light"]` (`--bg-page`, `--bg-primary`, `--accent`, `--ok`, `--warn`, `--danger`, `--line` и т.д.), без жёстких цветов
- Панели: скругление 6px, тень `var(--shadow-out)`, без жирных рамок; поля ввода: утопленные `var(--shadow-in)`, фокус — рамка `--accent`
- Строки списков/таблиц: разделитель `var(--line)`, зебра `var(--zebra)`, наведение `var(--hover)`, акцентная полоса слева
- Кнопки без рамки, скругление 4px, лёгкая тень; статусы — цветной тинт + полоса слева
- Одинаково выглядят `index.html` и `reference.html`, обе темы (тёмная по умолчанию, светлая)

## 💡 Всплывающие подсказки (Tooltips)

**Правило для всех новых элементов:**
- Каждая кнопка, поле ввода, иконка должны иметь `title` атрибут
- Описание должно быть развёрнутым (10-20 слов), объяснять ЗАЧЕМ и ЧТО делает элемент
- Формат: `title="Что делает элемент и как его использовать"`
- Примеры:
  - ✅ `title="Обновить переменные с ПЛК (сканирование OPC UA, может занять время)"`
  - ❌ `title="Обновить"` (слишком короткое)

**Для интерактивных элементов:**
- Кнопки → объясняем действие
- Иконки → объясняем статус (🟢 = на связи, ❌ = отключено)
- Чекбоксы → объясняем опцию (например, "Архив", "Grafana", "Авария")
- Фильтры → объясняем синтаксис поиска

## 📊 Best Practices для больших списков (50+ элементов)

**Минимальный набор функций:**

### ✅ Нумерация
- Используй порядковые номера (1., 2., 3., ...) перед элементами
- Помогает быстро ориентироваться и ссылаться на конкретный элемент
- Визуально похоже на Excel/Google Sheets - привычный формат для пользователей
- Особенно важно, когда элементы содержат длинные имена (обрезаются на экране)
- **Опционально:** кнопка показать/скрыть номера (№) для минималистичного вида
- Пример: `1. ClampSignal_MB060_FIX07_R_V44 (18 переменных)`

### 🔍 Поиск (фильтр)
- Обязательно добавь поле быстрого поиска для фильтрации по названию
- Поиск должен быть case-insensitive (игнорировать регистр)
- Работать в реальном времени (по мере ввода)
- Реагировать на Enter для явного применения фильтра
- Пример: `Поиск по блокам` → фильтрует Data Blocks по названию

### ↕️ Сортировка
- Добавь минимум 2 кнопки: сортировка A-Я и Я-А
- Кнопка активного порядка должна быть выделена цветом
- Сортировка должна применяться к уже отфильтрованным результатам
- Сохраняй выбор сортировки в session (пока страница открыта)
- Пример: `▲ А-Я` и `▼ Я-А` кнопки в контрольной панели списка

### 📈 Дополнительные рекомендации
- **Счётчик результатов:** если нужно, покажи сколько элементов найдено после фильтра
- **Группировка:** для очень больших списков (500+) добавь группировку по первым буквам
- **Скролл:** при клике на элемент сохрани позицию скролла для быстрого возврата
- **Сохранение состояния:** помни состояние сортировки и поиска при переключении ПЛК
- **Доступность:** убедись что кнопки управления легко нажимать (мин. 32x32px)
- **Эффективность:** используй debounce/throttle для поиска при очень больших списках
