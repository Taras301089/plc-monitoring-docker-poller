## Отложено

- **OPC UA Alarms & Conditions (S7-1500)** (15.10.2026): аварии из ПЛК с текстом и временем ПЛК без своего словаря битов. Не подходит сейчас: в программе UB нет вызовов `Program_Alarm`/ProDiag (аварии сделаны битами для WinCC), без переделки программы ПЛК получим только системную диагностику; включение A&C требует загрузки настроек в ПЛК. Решение за инженерами ПЛК. Проверка 15.10 на всех 8 ПЛК (GWM_UB, GWM_MB, GWM_BS, Chery_UB, Chery_MB, Changan, AE_WBS_1, AE_WBS_2; только чтение): у всех OPC UA V2.9.4, минимальный интервал выборки 1000 мс, `ConditionRefresh` отвечает «OK» у всех 8 ПЛК, но **аварии не передаются**: при активной аварии ProDiag на WBS по OPC UA ничего не пришло. По руководству Siemens (S7-1500 Communication, 11.3.6.4) нужно: свойства CPU → «PLC alarms» → «Central alarm management in the PLC», затем «OPC UA → Server → General» → «Enable alarms and conditions on the OPC UA server», загрузка в ПЛК. Придут ProDiag, GRAPH, системная диагностика, Program_Alarm. Риск: центральное управление сообщениями меняет хранение текстов аварий (панель HMI может потребовать перекомпиляции), начать с одного ПЛК (WBS_1). Версии CPU в проектах (15.10): WBS1 V2.9 (раздел A&C есть, central alarm management включён), Chery V2.8 (раздела A&C нет; нужен «Change device» на V2.9 с полной загрузкой и STOP; это F-CPU, подпись программы безопасности может измениться, нужна оценка ответственного за безопасность). Остальные ПЛК не проверены. Сборщик `ac_collector.py` уже подписан на все 8 ПЛК (флажок «Аварии ПЛК (OPC UA)»). В программах UB и Changan (выгрузки TIA) нет `Program_Alarm`/ProDiag, аварии своими FB на битах, поэтому по A&C придут только аварии ПЛК: системная диагностика (модули, приводы, Profinet). Можно сделать сейчас: сборщик A&C в поллере (`subscribe_alarms_and_conditions` на Server с AlarmConditionType i=2915, `ConditionRefresh` после подключения) → журнал «Аварии» как отдельный источник «ПЛК · диагностика»; правка поллера, нужно согласие (исход 2). Технологические аварии через A&C только после перевода на ProDiag/`Program_Alarm` в программах ПЛК (решение инженеров ПЛК)
