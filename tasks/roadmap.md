# Дорожная карта (общая): большие планы и идеи без исполнителя

Файл общий. Идея лежит здесь, пока её никто не взял. Кто берёт идею в работу, переносит её в свой файл `tasks/queue-<имя>.md` и ставит там себя исполнителем (а здесь строку удаляет или помечает «взято: имя»). Все пункты `[!]`: каждый требует плана и согласия пользователя по шагам.

Порядок и зависимости (предложение): аварии → Telegram → визуализация цеха (параллельно) → журнал из чатов → инструкции из чатов; обучение и табель независимы.

- R-1. [!] Визуализация всего цеха (сейчас на каскаде): схема цеха с состоянием оборудования; независима от остальных. Решить: источник схемы, какие сигналы показывать, формат экрана
- R-2. [!] Учёт рабочего времени персонала (табель). Риск: персональные данные и юридическая значимость; решить источник отметок (мастер, проходная, ПЛК), кто правит, сверка с кадровой системой. Зависит от: пользователи системы (есть)
- R-3. [!] Обучение персонала: справочник тем и отметки о прохождении по сотрудникам; простой модуль, независим
- R-4. [!] Ведение журнала из чатов: вызов техподдержки, описание проблемы и решения; бот читает рабочий чат, ИИ выделяет проблему, решение и автора. Риск: сообщения сотрудников попадают в базу и в модель; решить согласие, хранение, бюджет токенов. Зависит от: Telegram-бот
- R-5. [!] Автоматическое составление инструкций из сообщений в чатах (WhatsApp, Telegram). Строится на журнале из чатов (R-4)
- R-6. [!] Бэкапирование (очень важно). Сделано: `backup.ps1` (дампы и `status.json`), раздел «Бэкапы и место на диске» в справке для администратора. Осталось: расписание ежедневного бэкапа на сервере, копия вне сервера (правило 3-2-1), ежемесячная проверка восстановления на тестовой базе, оповещение при отсутствии свежего бэкапа (после Telegram). Исполнитель: сервер (см. `queue-server.md`)
- R-7. [!] Разделение экранов на производство и техобслуживание (отдельные вкладки или группа в меню, нумерация экранов). Решить с пользователем
- R-8. [!] Пилот: логика ПЛК из TIA Portal в виде XML (SimaticML через TIA Openness), «Почему сработала авария» с живыми значениями, снимок состояния при аварии. Нужны: версия TIA, язык блоков, наличие know-how и F-блоков. План по шагам в чате 13.10
