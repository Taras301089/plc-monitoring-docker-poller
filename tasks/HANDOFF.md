## 5. Рабочий процесс (проверен)

- Воркеры: Agent с `isolation: worktree`. Worktree создаётся из последнего коммита, поэтому в подсказке воркеру указывать, от какого коммита он работает, какие файлы не трогать, и просить перечислить изменённые файлы.
- Приём: сравнить файлы воркера с основной папкой (diff без CR), скопировать только изменённые; общие файлы (`reference.html`, `downtime.css`) объединять по разнице, не перезаписывать.
- После приёма: `docker compose build --no-cache fastapi-api`, `up -d`, проверить `docker ps`, `/api/env`, `docker logs`; для поллера пересобрать тоже, если менялся.
- Тесты: из папки `tests`, `python -m pytest -q`; один прогон за раз (около 11–14 минут, при параллельном втором ещё медленнее); база только `*_test` (защита в `conftest.py`). Последний прогон: 618 passed.
- Рабочие копии воркеров удалять: `git worktree remove -f -f ...`. После завершения воркеры иногда шлют дубли отчётов: останавливать `TaskStop`.
- Git Bash портит пути: для `docker exec` с путями использовать `MSYS_NO_PATHCONV=1`.
- Окончания строк: часть файлов CRLF (`history.py`, `index.html`, `archive.js`, `reports.js`, `kpi_collector.py`, `Dockerfile`, `reference.html`), сохранять как в основной.
