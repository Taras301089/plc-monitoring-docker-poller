🚀 Перенос на другой ПК (с базой, пользователями и настройками)

Все команды запускаются в PowerShell. Проверено: дамп базы восстанавливается на чистом сервере без потерь (пользователи, простои, план, настройки, теги ПЛК совпали по числу строк).

Требования к новому ПК

  • Windows 11 Pro, Docker Desktop (WSL2) и Git установлены; Docker Desktop запускается при входе в систему
  • Тот же сетевой доступ к ПЛК: адреса ПЛК (OPC UA) хранятся в базе и должны быть доступны с нового ПК
  • Постоянный (статический) IP-адрес, выключенный спящий режим, свободные порты 8000, 5432, 3000, 5678
  • Местное время завода задаёт параметр KPI_UTC_OFFSET_HOURS в docker-compose.yml: на сколько часов местное время отличается от UTC (сейчас 5, то есть UTC+5). Он определяет границы смен и суток (когда начинается новый день и интервалы), время на экранах Andon и время автосохранения отчётов. Часы самого ПК и пояс Windows на это не влияют. Если новый ПК стоит на том же заводе, ничего менять не нужно (значение переносится с кодом). Если пояс другой, измените число в обоих местах (fastapi-api и plc-monitoring-docker-poller) и перезапустите контейнеры
⚠ Выполняйте команды по одной. Вставляйте и запускайте каждую строку отдельно и дожидайтесь результата. Если две команды склеились в одну строку (например, git pushdocker compose stop …), ни одна из них не выполнится, а на экране это легко не заметить.

Часть А. На старом ПК (подготовка)

1
Сохранить код в Git
cd C:\plc-monitoring-docker-poller
git add -A
git commit -m "Перед переносом на новый ПК"
git push
Без этого на новом ПК будет старая версия. Файл .env в Git не попадает (см. шаг 4).
Проверка: git status -sb не должен показывать ahead (это значит, что отправлено не всё).
2
Остановить запись данных (на время переноса, чтобы дамп был полным)
docker compose stop fastapi-api plc-monitoring-docker-poller
Экраны Andon на это время недоступны: переносите в нерабочее время.
Проверка: выполните docker ps. Должны остаться только postgres_db, n8n_app и grafana_app (база должна работать, из неё снимается дамп). Если fastapi_api и python-async-poller всё ещё в списке, остановка не сработала: дамп сейчас снимать нельзя.
3
Снять дампы баз
powershell -NoProfile -ExecutionPolicy Bypass -File C:\plc-monitoring-docker-poller\backup.ps1
Одна команда снимает обе базы в C:\plc-backups: файлы hub_ГГГГ-ММ-ДД.dump (основная база) и n8n_ГГГГ-ММ-ДД.dump. Проверьте, что hub_….dump не пустой (около 3 МБ и более). Дамп для переключения снимается после остановки (шаг 2): снятый раньше не содержит последних изменений.
4
Собрать файлы для переноса в одну папку (флешка или сетевая папка):
  • Файлы hub_ДАТА.dump и n8n_ДАТА.dump из C:\plc-backups
  • C:\plc-monitoring-docker-poller\python-async-poller\.env
  • Папки grafana_data и n8n_data (если используются; перед копированием docker compose stop grafana n8n)
  • Папка отчётов C:\Andon-Reports

Часть Б. На новом ПК

5
Получить код и разложить файлы
git clone <адрес вашего репозитория> C:\plc-monitoring-docker-poller
cd C:\plc-monitoring-docker-poller
copy <флешка>\.env python-async-poller\.env
xcopy <флешка>\grafana_data grafana_data /E /I
xcopy <флешка>\n8n_data n8n_data /E /I
xcopy <флешка>\Andon-Reports C:\Andon-Reports /E /I
Если диска C: для отчётов нет или нужен другой путь, создайте в корне проекта файл .env со строкой REPORTS_HOST_DIR=D:/Andon-Reports.
6
Запустить только базу данных
docker compose up -d postgres
timeout /t 20
На пустом томе PostgreSQL сам создаёт две пустые базы по init.sql.
7
Восстановить данные (пересоздаём пустую базу и загружаем в неё дамп)
docker cp C:\plc-backups\hub_ДАТА.dump postgres_db:/tmp/hub.dump
'DROP DATABASE "general_data_hub_BD" WITH (FORCE);' | docker exec -i postgres_db psql -U n8n_user -d postgres
'CREATE DATABASE "general_data_hub_BD";' | docker exec -i postgres_db psql -U n8n_user -d postgres
docker exec postgres_db pg_restore -U n8n_user -d general_data_hub_BD --no-owner /tmp/hub.dump
Имя файла: ДАТА замените на дату из имени вашего файла. Если дамп снимали вручную без скрипта, файл называется просто hub.dump (и n8n.dump для N8N): тогда в первой команде пишите C:\plc-backups\hub.dump.
Предупреждения «errors ignored on restore» безвредны (служебные права). Для N8N повторите то же с n8n_ДАТА.dump и базой n8n_db.
8
Проверить, что данные на месте
docker exec postgres_db psql -U n8n_user -d general_data_hub_BD -c "select (select count(*) from app_users) users, (select count(*) from plcs) plcs, (select count(*) from kpi_hourly) hourly, (select count(*) from kpi_downtime_items) downtimes"
Сравните числа с теми же запросом на старом ПК: они должны совпасть.
9
Запустить всё остальное
docker compose up -d --build
docker compose ps
Все контейнеры должны быть в состоянии running. Недостающие таблицы приложение создаёт само при запуске.
10
Открыть доступ по сети и проверить
New-NetFirewallRule -DisplayName "PLC Monitoring 8000" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow
  • Откройте http://localhost:8000 и войдите под администратором (пароли переехали вместе с базой)
  • Andon: значок «● LIVE» и живые цифры (иначе нет связи с ПЛК, проверьте сеть и адреса во вкладке «Переменные ПЛК»)
  • Вкладки Графики, Отчёты, Простои, Пользователи: данные за прошлые дни на месте
  • Отчёты: «Сохранить сейчас» создаёт файл в папке отчётов

Часть В. Переключение

11
Отключить старый ПК и переключить пользователей
  • На старом ПК docker compose down: две работающие системы одновременно не допускаются (обе пишут в ПЛК и сменные данные)
  • Старые данные и дампы храните минимум 2 недели
  • Новый адрес: http://<IP нового ПК>:8000. Обновите закладки и телевизоры: на каждом открыть новый адрес, один раз войти (tv1) и включить «Режим табло»: вход и выбранная линия запоминаются отдельно для каждого адреса
  • Все пользователи входят заново (сессии привязаны к адресу)
12
Настроить ежедневный бэкап на новом ПК
schtasks /Create /SC DAILY /ST 03:00 /TN "PLC backup" /TR "powershell -NoProfile -ExecutionPolicy Bypass -File C:\plc-monitoring-docker-poller\backup.ps1"
Скрипт backup.ps1 лежит в корне проекта: кладёт дампы обеих баз в C:\plc-backups и удаляет дампы старше 30 дней. Раз в неделю копируйте эту папку на другой диск или в сетевую папку.
✓

Откат, если что-то пошло не так

Старый ПК остаётся нетронутым (шаг 2 лишь остановил контейнеры): выполните на нём docker compose up -d, а на новом docker compose down. Потеряются только данные, накопленные после остановки.

Безопасность после переноса

  • Адрес репозитория (git remote -v) не должен содержать токен GitHub: храните доступ в «Диспетчере учётных данных» Git. Если токен был открыт в адресе, его нужно отозвать на GitHub и выпустить новый
  • Пароль базы my_strong_password в docker-compose.yml стоит заменить на свой (изменить в docker-compose.yml, python-async-poller/.env и пользователе PostgreSQL); сделайте это отдельным шагом после проверки переноса
  • Порты 5432 (база), 3000 (Grafana) и 5678 (N8N) без надобности не открывайте в брандмауэре для сети

🔧 Решение проблем

❌ Команда «не сработала», хотя ошибки нет

  • Проверьте, не склеились ли две команды в одну строку (например, git pushdocker compose stop): вставляйте и запускайте по одной
  • После остановки проверьте результат: docker ps; после git push: git status -sb (не должно быть ahead)

❌ Команда «не сработала», хотя ошибки нет

  • Проверьте, не склеились ли две команды в одну строку (например, git pushdocker compose stop): вставляйте и запускайте по одной
  • После остановки проверьте результат: docker ps; после git push: git status -sb (не должно быть ahead)

❌ Контейнеры не запускаются

  • Проверьте, запущен ли Docker Desktop
  • Проверьте порты: не занят ли 5432, 8000, 5678, 3000
  • Просмотрите логи: docker compose logs

❌ БД не инициализируется

  • Остановите контейнеры (docker compose down) и переименуйте папку pg_data (данные базы лежат в ней; сначала сделайте дамп, если база уже работала)
  • Пересоздайте контейнеры: docker compose down && docker compose up -d

❌ Веб-интерфейс показывает старый код

  • Очистьте кэш браузера: Ctrl+Shift+R
  • Или пересоберите контейнер: docker compose build --no-cache fastapi-api && docker compose up -d fastapi-api

❌ ПЛК не подключается

  • Проверьте адрес ПЛК (OPC UA) во вкладке «Переменные ПЛК» и доступность ПЛК по сети с этого ПК
  • Убедитесь, что ПЛК в сети и включена OPC UA
  • Посмотрите логи Poller: docker logs python-async-poller

Версия проекта: 1.0.0

Сборка: Иерархический браузер переменных + поиск по Data Block (Instance & Global) + кэширование БД

Global Data Blocks: Автоматическое обнаружение (Namespace 3), кэширование, поиск и фильтрация по 1100+ переменным

Структурные теги (массивы и структуры, как в WinCC): раскрываются по клику ▷, вложенные элементы подгружаются с ПЛК через API /api/plcs/{id}/opcua/children

Галочка у переменной сразу сохраняет её в БД (таблица plc_tags, тип DIGITAL/ANALOG определяется по типу данных ПЛК), снятие галочки отключает тег; A/G/L — архив, Grafana, авария. Кнопки «Обновить с ПЛК» и «Из БД» находятся в панели Data Blocks, там же дата и время последнего сканирования

Колонка «Значение» показывает текущие значения переменных из ПЛК в реальном времени: раз в секунду читаются только видимые на экране строки (до 80), пакетным запросом через POST /api/plcs/{id}/opcua/values; значок LIVE в заголовке области «Переменные» показывает состояние обновления, при чтении также определяется тип данных

Вкладка «Andon / KPI» (Dashboard, информационная панель) повторяет KPI-экраны SCADA: для выбранного ПЛК находит блоки почасового счётчика кузовов (*_counting_numbers_of _Body_by_the_hours_DB), по кнопкам выбирается линия (GWM, Chery, Changan). Таблица: интервал, минуты, план, количество кузовов, отклонение, такт-тайм за период, итого и средний такт смены; слева текущий такт между кузовами; дата и время — с сервиса на ПК (GET /api/time, смещение KPI_UTC_OFFSET_HOURS), а не часы браузера телевизора. Обновление раз в секунду. Начало интервалов берётся из ПЛК, окончание и план задаются кнопкой «Смена и план» и хранятся в таблице kpi_schedule (создаётся автоматически при запуске API)

Переменные блока показываются плоским нумерованным списком; в OPC UA видны только переменные с флагом «Accessible from HMI/OPC UA» в TIA Portal
