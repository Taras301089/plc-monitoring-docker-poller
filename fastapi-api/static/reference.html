Автоматический бэкап

База данных автоматически бэкапируется каждый день в папку ./backups/

Это происходит благодаря скрипту в docker-compose.yml

🚀 Развёртывание на другом ПК

Требования

  • Windows 11 Pro (с WSL2)
  • Docker Desktop установлен и запущен
  • Git установлен

Пошаговый план

1
Клонировать репозиторий
git clone https://github.com/YOUR_USER/plc-monitoring-docker-poller.git C:\plc-monitoring-docker-poller
2
Перейти в папку проекта
cd C:\plc-monitoring-docker-poller
3
Создать папку для бэкапов (если нужно восстановление)
mkdir backups

Если у вас есть старые бэкапы БД — скопируйте файлы *.sql в эту папку

4
Запустить все контейнеры
docker compose up -d

Подождите 30 сек, пока PostgreSQL инициализируется

5
Если нужно восстановить БД из бэкапа
docker exec plc-monitoring-docker-poller-postgres-1 psql -U postgres < backups/backup_ДАТА.sql

Замените ДАТА на актуальную дату файла бэкапа

6
Открыть веб-интерфейс
http://localhost:8000

Браузер переменных ПЛК будет доступен по этому адресу

✅ Проект развёрнут!

  • Веб-интерфейс: http://localhost:8000
  • API: http://localhost:8000/api/
  • N8N (если включен): http://localhost:5678
  • Grafana (если включен): http://localhost:3000

⚡ Оптимизации для упрощения переноса

1. Использование .env файла

Все переменные окружения (IP ПЛК, логины БД) хранятся в .env

При переносе просто отредактируйте этот файл под новые значения:

PLC_IP=192.168.1.100 POSTGRES_PASSWORD=your_secure_password POSTGRES_DB=general_data_hub_BD

2. Docker volumes вместо хост-папок

Все данные хранятся в Docker томах (./pg_data/, ./n8n_data/, и т.д.)

Это делает систему независимой от операционной системы и легче переносится между машинами

3. Git для кода

Весь исходный код в Git — просто git clone и готово

4. SQL дампы для БД

Вместо копирования томов, используются SQL дампы, которые легче архивировать и распространять

5. Скрипт быстрого развёртывания (рекомендуется)

Можно создать batch-скрипт для автоматизации:

@echo off git clone https://github.com/YOUR_USER/plc-monitoring-docker-poller.git cd plc-monitoring-docker-poller docker compose up -d echo Ожидание инициализации БД... timeout /t 30 echo. echo ✅ Проект запущен! Откройте http://localhost:8000 pause

🔧 Решение проблем

❌ Контейнеры не запускаются

  • Проверьте, запущен ли Docker Desktop
  • Проверьте порты: не занят ли 5432, 8000, 5678, 3000
  • Просмотрите логи: docker compose logs

❌ БД не инициализируется

  • Удалите volume: docker volume rm plc-monitoring-docker-poller_pg_data
  • Пересоздайте контейнеры: docker compose down && docker compose up -d

❌ Веб-интерфейс показывает старый код

  • Очистьте кэш браузера: Ctrl+Shift+R
  • Или пересоберите контейнер: docker compose build --no-cache fastapi-api && docker compose up -d fastapi-api

❌ ПЛК не подключается

  • Проверьте IP адрес ПЛК в .env файле
  • Убедитесь, что ПЛК в сети и включена OPC UA
  • Посмотрите логи Poller: docker logs plc-monitoring-docker-poller-plc-monitoring-docker-poller-1
