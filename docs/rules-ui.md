## ↕️ Порядок элементов: перетаскиванием, у каждого свой

- Порядок вкладок верхнего меню, пунктов выпадающих списков (Andon, Аварии) и списка ПЛК каждый пользователь меняет **под себя перетаскиванием** (захватил надпись и перенёс выше или ниже), а **не стрелками**. Порядок хранится на сервере у вошедшего пользователя (ключи `order-…`), у невошедших (табло) порядок по умолчанию, который задаёт администратор. Работает и пальцем на сенсорном экране (pointer events)

## Веб-интерфейс PLC Variable Browser

**Путь**: `fastapi-api/static/index.html`  
**API сервер**: `fastapi-api/main.py`  
**Три области вкладки «Переменные ПЛК»** (называть именно так):
1. **ПЛК** — выбор и настройка ПЛК (добавить/изменить/удалить), дата последнего обновления с ПЛК
2. **Блоки данных** — список Data Blocks, кнопки «Обновить с ПЛК» / «Из БД», поиск и сортировка
3. **Переменные** — переменные выбранного блока (плоский нумерованный список, структуры раскрываются)

**Функции**:
- Иерархическое отображение переменных (древовидная структура как в WinCC)
- Развернуть/свернуть Data Blocks
- Поиск по Data Block и имени переменной
- Выбор переменных для сохранения
- Опции: архивирование, Grafana, авария

## 🎨 Стиль оформления: Flat Dark (плоский тёмный с акцентами)

- Цвета только через CSS-переменные из `:root` / `[data-theme="light"]` (`--bg-page`, `--bg-primary`, `--accent`, `--ok`, `--warn`, `--danger`, `--line` и т.д.), без жёстких цветов
- Панели: скругление 6px, тень `var(--shadow-out)`, без жирных рамок; поля ввода: утопленные `var(--shadow-in)`, фокус — рамка `--accent`
- Строки списков/таблиц: разделитель `var(--line)`, зебра `var(--zebra)`, наведение `var(--hover)`, акцентная полоса слева
- Кнопки без рамки, скругление 4px, лёгкая тень; статусы — цветной тинт + полоса слева
- Одинаково выглядят `index.html` и `reference.html`, обе темы (тёмная по умолчанию, светлая)

## ⚙️ Настройки видны в интерфейсе

- Каждая настройка, которая хранится в базе и влияет на поведение системы (флаг, режим, время), имеет элемент управления в интерфейсе (чекбокс, переключатель, поле) с `title`; менять её может только та роль, которой это разрешено, и право проверяется на сервере. Настройка, которую можно изменить только в базе, считается недоделкой (пример: «Включён в опрос» у ПЛК)
- **Настройки, одинаковые для многих объектов (ПЛК, линии, проекты), ставятся сразу для всех в одном общем месте, а не по одному через «Редактировать» у каждого объекта.** Это общая таблица или панель: строка на объект, в каждой строке галочка или поле, сверху «выбрать все» и одна кнопка «Применить» (или сохранение при каждой галочке). Пользователь открыл один раз, отметил нужное для всех и закрыл, не переходя от объекта к объекту. Редактирование одного объекта остаётся только для его уникальных данных (имя, адрес). Образец: «Автосохранение отчётов» на вкладке «Отчёты» (таблица линий с галочками)

## 💡 Всплывающие подсказки (Tooltips)

**Правило для всех новых элементов:**
- Каждая кнопка, поле ввода, иконка должны иметь `title` атрибут
- Описание должно быть развёрнутым (10-20 слов), объяснять ЗАЧЕМ и ЧТО делает элемент
- Формат: `title="Что делает элемент и как его использовать"`
- Примеры:
  - ✅ `title="Обновить переменные с ПЛК (сканирование OPC UA, может занять время)"`
  - ❌ `title="Обновить"` (слишком короткое)

**Для интерактивных элементов:**
- Кнопки → объясняем действие
- Иконки → объясняем статус (🟢 = на связи, ❌ = отключено)
- Чекбоксы → объясняем опцию (например, "Архив", "Grafana", "Авария")
- Фильтры → объясняем синтаксис поиска

## 📑 Таблицы работают как в Excel

Пользователи привыкли к Excel, поэтому в больших таблицах **максимально использовать его функции и лучшие практики**:
- **Сортировка** по любому столбцу кликом по заголовку (по возрастанию, по убыванию, сброс), с индикатором стрелкой; Shift+клик добавляет второй уровень сортировки
- **Фильтры в заголовках** столбцов: список значений с чекбоксами и поиском, отметка столбцов с активным фильтром, кнопка «Сбросить фильтры»
- **Выделение и копирование**: выделение ячейки, диапазона (мышью или Shift+клик), столбца (Ctrl+клик по заголовку), всей таблицы (Ctrl+A); Ctrl+C копирует в буфер как текст с табуляцией, чтобы вставлялось в Excel; кнопка «Копировать таблицу»
- В каждой строке **все ячейки заполнены** (без «объединённых» пустых ячеек), чтобы сортировка, фильтры и копирование не теряли данные; повторяющиеся значения можно лишь приглушить цветом. **Исключение: числа, которые суммируют** (план, факт, минуты интервала при нескольких строках на один интервал): они записываются один раз, на первой строке группы, иначе сумма столбца в Excel завышается. Внизу таблицы строка «Итого» с формулами `SUM`, значения в ней должны совпадать с плитками на экране
- Порядок столбцов от общего к частному (например, Бренд, Участок, Станция); числа выровнять, у каждого заголовка `title`
- **Ширина столбцов меняется перетаскиванием границы в заголовке (как в Excel) во всех больших таблицах** (Andon, Простои, Пользователи, Справочники и новые): подключать `window.attachColWidths(table, "ключ")` из `colwidths.js` после каждой отрисовки таблицы; ширины хранятся на сервере (личные у вошедшего пользователя; администратор с Shift при отпускании сохраняет общие для всех и для табло), двойной щелчок по границе возвращает по умолчанию, у ручки есть `title`
- Позже: выгрузка в Excel (.xlsx), закрепление шапки при прокрутке

## 🚫 Не дублировать надписи

- Заголовок внутри вкладки **не повторяет название самой вкладки** (во вкладке «Простои» нет заголовка «Простои», в «Пользователи» нет «Пользователи»): название уже видно в панели навигации
- Одно и то же не писать дважды на экране: в заголовке и подзаголовке, в подписи и рядом в подсказке-тексте
- Достаточно короткого описания (что здесь можно сделать) и самих элементов; подробности уходят в `title`
- **Один факт не показывается дважды в одном элементе:** цвет, значок или точка уже говорят о состоянии, поэтому текст рядом не повторяет его словами (пример: зелёная точка у ПЛК уже значит «связь есть», справа пишется только когда было последнее обновление с ПЛК, без слов «опрос»/«связь есть»; у красной точки справа время и причина, без слов «нет связи»)

## 📊 Best Practices для больших списков (50+ элементов)

**Минимальный набор функций:**

### ✅ Нумерация
- Используй порядковые номера (1., 2., 3., ...) перед элементами
- Помогает быстро ориентироваться и ссылаться на конкретный элемент
- Визуально похоже на Excel/Google Sheets - привычный формат для пользователей
- Особенно важно, когда элементы содержат длинные имена (обрезаются на экране)
- **Опционально:** кнопка показать/скрыть номера (№) для минималистичного вида
- Пример: `1. ClampSignal_MB060_FIX07_R_V44 (18 переменных)`

### 🔍 Поиск (фильтр)
- Обязательно добавь поле быстрого поиска для фильтрации по названию
- Поиск должен быть case-insensitive (игнорировать регистр)
- Работать в реальном времени (по мере ввода)
- Реагировать на Enter для явного применения фильтра
- Пример: `Поиск по блокам` → фильтрует Data Blocks по названию

### ↕️ Сортировка
- Добавь минимум 2 кнопки: сортировка A-Я и Я-А
- Кнопка активного порядка должна быть выделена цветом
- Сортировка должна применяться к уже отфильтрованным результатам
- Сохраняй выбор сортировки в session (пока страница открыта)
- Пример: `▲ А-Я` и `▼ Я-А` кнопки в контрольной панели списка

### 📈 Дополнительные рекомендации
- **Счётчик результатов:** если нужно, покажи сколько элементов найдено после фильтра
- **Группировка:** для очень больших списков (500+) добавь группировку по первым буквам
- **Скролл:** при клике на элемент сохрани позицию скролла для быстрого возврата
- **Сохранение состояния:** помни состояние сортировки и поиска при переключении ПЛК
- **Доступность:** убедись что кнопки управления легко нажимать (мин. 32x32px)
- **Эффективность:** используй debounce/throttle для поиска при очень больших списках

## 📏 Экономия высоты: компоновать компактно

- Экран должен показывать как можно больше без прокрутки: **высота дороже ширины**. Всё, что помещается в одну строку, ставится в одну строку (период и фильтры, кнопки и счётчики), а не в отдельные строки друг под другом
- Однотипные блоки (два графика, две плитки, две таблицы) ставятся **рядом**, а не друг под другом; на узком окне они сами переносятся вниз (`grid`/`flex-wrap`)
- Графики и плитки делаются **не крупнее, чем нужно для чтения**: низкие (высота 150–250px), без пустых полей вокруг, подписи не больше мелкого размера
- Лишние заголовки, пояснения и пустые отступы убираются (см. «Не дублировать надписи»); подробности уходят в `title`
- Новый экран проверяется при высоте окна около 900px: ключевые данные видны без прокрутки

## 📐 Адаптивная вёрстка (разные экраны и устройства)

Сайт открывают на мониторе, ноутбуке с масштабом Windows 125–150%, в окне на пол-экрана и на телевизоре, поэтому:
- **Никаких наложений:** нельзя ставить блоки поверх контента через `position: absolute/fixed`, если их ширина может расти (группы кнопок, плитки, индикаторы). Блок, которому не хватает места, переносится на новую строку или уходит под соседа (flex-wrap, grid), а не залезает на соседа
- **Новая кнопка или плитка в шапке** = проверка, что шапка не ломается при ширине 955px; если не помещается, правило для узкого окна (`@media (max-width: ...)`) добавляется сразу
- **Размеры шрифтов таблицы задаются одним общим правилом** (`clamp()` от высоты и ширины окна), а не отдельным размером для каждой колонки; заголовки колонок тоже масштабируются по ширине
- **Новые стили и скрипты** подключаются через главную страницу: адреса получают версию автоматически (`?v=`), старый кэш на ноутбуках и телевизорах не держится
- **После любой правки вёрстки** запускать проверку `/check-layout`: она открывает страницу в типичных размерах, ищет наложения и обрезанный текст и присылает скриншоты. Финально проверяют на реальных устройствах (ноутбук пользователя, телевизор)

## 🔤 Шрифты и размеры (единый вид по всему сайту)

- **Шрифтов (семейств) на всём сайте не больше двух:** `Segoe UI` (с запасными Roboto, Arial) для текста и цифр. Второй при необходимости только для кода или имён переменных ПЛК. Цифры таблиц в том же шрифте с `font-variant-numeric: tabular-nums`, без отдельного моноширинного шрифта и перечёркнутых нулей
- **Размеров шрифта на одном экране не больше трёх:** мелкий (подписи, заголовки колонок, причины, кнопки, подсказки), крупный (числа и время в таблицах Andon, значения в плитках) и заголовочный (название бренда, такт-тайм, часы). Одинаковые элементы всегда одного размера; разовые размеры «для одной колонки» не вводить
- **Размеры одни и те же на всех экранах сайта:** значения задаются переменными в `:root` (`--fs-small`, `--fs-large`, `--fs-title`), а не числами в каждом правиле. Новый элемент берёт размер из этих переменных
- Подсказки и мелкие служебные подписи (tooltips, номера строк) в счёт не идут, но тоже берутся из переменных
- На обычных экранах значения такие: мелкий 13px, крупный 16px, заголовочный 22px. На Andon своя шкала под телевизор (плавающие размеры в `#andon`, в режиме табло мелкий крупнее). Панель навигации сверху и значок темы это общий каркас, в счёт размеров экрана не входят (мелкий 13px)

## 🎨 Цвета (не более трёх акцентных)

- Акцентных цветов на экране три: **зелёный, красный, синий**. Всё остальное нейтральное (белый, оттенки серого, фоны)
- Значения: зелёный = норма и факт (`--ok`); красный = проблема, простой, отставание (`--danger`); синий = действия и выбранное: активная вкладка, фокус, ссылки, главная кнопка (`--accent`)
- Жёлтый и оранжевый (`--warn`) не использовать: перерыв, обед, пауза показываются нейтральным серым с подписью
- Цветом выделяются значения и состояния, а не обычный текст: основной текст белый, второстепенный серый
- Оттенки одного цвета (бледная подложка, мягкий красный) допустимы и не считаются новым цветом
- Правило относится к цвету текста, подсветок, рамок и фонов
- **Цветная точка у ПЛК означает только наличие связи** (последний опрос успешен: зелёная; нет связи: красная). Флаг «Включён в опрос» точкой не показывается: выключенный ПЛК виден приглушённой строкой и чекбоксом в окне редактирования

## ✍️ Единый порядок «содержание, затем автор»

Везде, где рядом показаны текст и его автор (причина простоя, комментарий, примечание, строка отчёта и Excel):
- **Сначала содержание, затем автор** мелким серым в конце: `текст · Фамилия, должность`
- Автор записывается как **«Фамилия, должность»** (должность по роли: Мастер, Начальник участка и т.д.), без префиксов «Внёс:» на экране Andon
- Пример: `UB-20 · Оборудование. Работа ОТО · Исимов, Начальник участка`, затем `сломал датчик · Иванов, Мастер` (комментарий выглядит как продолжение описания простоя, без значка пузыря: это то же описание, только от другого отдела)
- Порядок «автор: текст» не использовать; в подсказке автор в скобках после текста
- **Комментарий начинается с разделителя «↳»** (серый): так видно, что это ответ или дополнение к описанию выше, а не новая причина; значок пузыря не используется
- Число видимых строк в ячейке «Причина» считается **по видимым интервалам** (скрытые неактивные интервалы не учитываются), иначе строки комментариев пропадают

## 🗑 Удаление записей

- **Удаляет только автор записи и администратор** (описание простоя, комментарий и любые похожие записи); начальники и остальные чужое не удаляют. Правило проверяется на сервере, а не только скрытием кнопки
- **Кнопка называется «Удалить»** (текстом), а не крестиком «✕»: действие должно быть понятно без догадок
- **История сохраняется в базе:** удаление не стирает данные. Комментарии помечаются `deleted_at`; удалённые строки описания копируются в журнал `kpi_downtime_items_log` (что было, кто создал, кто и когда удалил). Новые удаляемые сущности делаются по тому же принципу

## 📐 Колонка «Причина» использует всю ширину

- Каждая причина простоя выводится **своей колонкой** (причина, описание, комментарий; колонки идут слева направо), «не описано N мин» отдельной колонкой в конце. Скрывать причину нужно, только если она реально не помещается по ширине ячейки; тогда показывается «+N»
- Нельзя скрывать текст «по привычной норме строк», пока справа есть свободное место
